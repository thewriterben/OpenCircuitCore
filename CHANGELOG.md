# Changelog

## [Unreleased]

### Added (2026-11-05) — sensor-node fab package
- `scripts/add_ground_pour.py`: GND zone on each copper layer from the Edge.Cuts box, filled with pcbnew's `ZONE_FILLER`; clearance 0.30 mm, thermal reliefs, unconnected islands removed; re-running replaces its own zones by name. Run after routing. On `sensor-node` the fill stops at y = 13.25 mm, the module footprint's antenna keepout.
- `boards/sensor-node/sensor-node.kicad_dru`: the `npth_min_hole` rule, re-proven on this board per ADR-0006 (at 5.0 mm it flags H1–H4 and nothing else). DRC after pour: **0 violations, 0 unconnected**; warnings are silkscreen only.
- `boards/sensor-node/fab/`: 9 Gerber layers (copper, mask, paste, silk, edge; no empty user layers), job file, Excellon drill (34 holes, matching 12 thermal vias + 8 routed vias + 10 header pins + 4 M3), KiCad placement CSV. `emit_provenance.py` now hashes `fab/*.csv`; 15 outputs verified.

### Changed (2026-11-04) — sensor-node routed clean
- `boards/sensor-node`: **routed** with FreeRouting 2.5.0 (jar on Java 25): 143 tracks, 8 vias, **DRC 0 violations, 0 unconnected** against `fab-profiles/jlcpcb-2layer-1oz` (applied before routing, as on `sensor-breakout`). STEP/STL re-exported from the routed board; provenance re-emitted, 47 artifacts verified.
- `scripts/route_board.py`: `--java` for a `.jar` router (2.5.0 needs Java 25; the native `freerouting-cli.exe` hangs after loading the DSN, upstream #957); `--router.automatic_neckdown=false` in the router command, with the measured caveat that it reduces but does not remove 0.15 mm fanout stubs at the module's pad pitch; DRC parser reads kicad-cli's report wording (`** Found N DRC violations **` / `unconnected pads`) and normalises the report to LF, so `routing.json` now carries real numbers and `routed_clean` instead of `None`.

### Added (2026-11-04) — Phase 2: a device, not a subcircuit
- `boards/sensor-node/` + `scripts/make_sensor_node.py` / `make_sensor_node_board.py`: ESP32-S3-WROOM-1 + BME280 + 1x04 sensor header + 1x06 programming header. 13 parts, 44 pin connections, 8 nets; **ERC 0 violations** (every unused module pin carries an explicit `no_connect`, now emitted by the shared generator), 44 × 52 mm board, **DRC 0 violations, 34 unconnected** (unrouted by design). STEP/STL exported. Provenance emitted and verified.
- `make_reference_schematic.build(parts, out, project)`: the schematic generator is a function; `PARTS`/`main()` unchanged for the reference subcircuit. Writes LF regardless of platform (the provenance checker's `.gitattributes` rule).
- `scripts/lf.py` and `to_lf()` in the board/routing scripts: every design source and report is LF the moment it is written, so `emit_provenance.py` no longer refuses Windows-generated boards.
- `scripts/route_board.py`: headless routing, `pcbnew.ExportSpecctraDSN` → FreeRouting 2.x (`-de -do -mp --gui.enabled=false`) → `ImportSpecctraSES` → `kicad-cli pcb drc`; `routing.json` hashes every input and output. Exit 3 with the DSN kept when the router is not on disk, which is the state in this repo until FreeRouting is downloaded. GPL-3.0 at the process boundary, same rule as KiCad.
- `scripts/make_firmware.py`: **firmware pins from the netlist.** Finds the module's `IOnn` pin on the sensor's SDI/SCK nets (GPIO8/GPIO9 here), the BME280 address from where SDO is tied (0x76; Bosch datasheet §6.2), refuses CSB not high, SDO floating, or a bus pin in the module's cited strapping/USB list (OpenPartsCore `attributes.strapping_pins`). Emits `pins.rs` (OBC-Prime `Board.i2c` shape), `pins.h`, and `firmware.manifest.json` with a *proposed* `espflash` command, `executed: false`. Refusal tested: SDA on GPIO0 → exit 2, nothing written.

### Added

### Changed
- **ADR-0003 supersedes ADR-0001: KiCad directly, atopile dropped.** Established by installing it: the `atopile` CLI is maintenance-only (0.15.8 last release, pins Python 3.14, `zstd` has no cp314 wheel so it needs MSVC Build Tools), and 0.16+ moved to a hosted browser workspace. A SaaS dependency in the design path conflicts with a platform that is local-first everywhere else. Toolchain verified present: KiCad 10.0.5 with `kicad-cli` (`sch erc`, `sch export`, `pcb drc`, `pcb export` incl. gerbers, drill, ODB++, IPC-D-356, STEP, STL).
- Architecture updated: the board→enclosure co-design path is now a verified mechanism (`pcb export step|stl` into OpenDesignCore's mesh import boundary) rather than a "format TBD" placeholder.

### Added
- `scripts/make_reference_board.py` + `boards/reference-esp32s3/`: first board through the toolchain, generated deterministically with KiCad's own `pcbnew` API — 30 × 40 mm outline, 4 × M3 mounting holes. **DRC: 0 violations, 0 unconnected.** STEP and STL exported.
- Co-design bridge exercised for real: the exported STL feeds OpenDesignCore's mesh import boundary and produces an enclosure fitted to the actual board geometry (ODC run 3). This turned ADR-0003's claimed path into a tested one — and surfaced that `kicad-cli` emits **ASCII** STL, which PicoGK refuses; fixed in OpenDesignCore PR #8.

Scope note: geometry only. No schematic, netlist, or components yet — the carrier size and hole inset are placeholders, not cited values, until a schematic constrains them.
- `boards/sensor-breakout` + `scripts/make_sensor_breakout.py`: the first board whose **connectivity is derived from its schematic**. Parts come from `make_reference_schematic.PARTS` (one source of truth for both) and pads are bound to nets parsed from the schematic's exported netlist, using `NETINFO_ITEM` + `pad.SetNet`. Result: **0 DRC violations, 10 unconnected items** — correct nets, unrouted ratsnest, which is the honest state to hand to a router. Verified from the saved file that U2's pads carry GND/+3V3/SDA/SCL as the schematic specifies.
- Closes the gap named in `reference-esp32s3`: there, schematic and board were generated independently with nothing stopping them disagreeing.
- `scripts/emit_provenance.py`: every board build now emits a provenance record — design sources and their hashes, upstream netlist (so a board whose nets came from another directory's schematic says so), outputs, ERC/DRC results, KiCad version, commit. Canonicalisation is byte-identical to Project BINGO's kernel and OpenDesignCore's C# port, so hashes computed here are comparable there; floats are refused for the same reason. Closes the invariant this repo was failing while OpenDesignCore held it.
- Two parsing bugs found by running it rather than trusting it: KiCad writes `Found 0 DRC violations` in reports but `Found 0 violations` on the console, and **ERC reports use an entirely different shape** (`** ERC messages: 0  Errors 0  Warnings 0`). The first version silently recorded "unknown" and called it a build; it now refuses to emit a record claiming a check happened whose result it could not read.
- `fab-profiles/jlcpcb-2layer-1oz.json` + `scripts/apply_fab_profile.py`: a manufacturer's published capability, **cited to the vendor's page**, applied to a board's design settings so DRC asks the question that matters — not "is this self-consistent" but "will this house build it". `sensor-breakout` passes JLCPCB's stated 2-layer 1 oz minimums with 0 violations. The script refuses to apply a profile with no citation.
- Four capabilities are listed as **deliberately not encoded** rather than approximated, including the via annular minimum: the vendor states a PTH annular ring but no via-specific figure, and deriving one would have been inventing a tolerance. Marked TODO(source).
- Gerbers and drill exported to `boards/sensor-breakout/fab/` (25 layer files + drill); all 26 now hashed into the provenance record.
- occ_mcp: stdio MCP surface - list_boards, get_bom, get_provenance, list_fab_profiles, verify. All execute; verify's only writes are regenerable check reports. ADR-0005: regeneration is deliberately NOT exposed, because this repo's writes are design files a human also edits and an agent regenerating over an evening's routing has no undo.
- Registration must use an absolute script path: 'python -m occ_mcp.server' resolves against the client's working directory and fails from anywhere but this repo. Found by doing it wrong and watching it fail.
- Custom DRC rules (boards/sensor-breakout/sensor-breakout.kicad_dru) for capabilities KiCad has no board-wide setting for. ADR-0006: a rule ships only once proven to FIRE, not merely to parse - set the threshold absurdly, confirm DRC reports a violation naming the rule, restore.
- This immediately caught a would-be false positive: the NPTH annular-ring rule parses cleanly and never fires (KiCad 10.0.5 does not evaluate annular_width for NPTH pads; min 9.0mm against a 0.00mm annulus reported nothing). Withdrawn and documented rather than shipped as fake coverage.
- .kicad_dru added to provenance DESIGN_SOURCES: a record saying DRC passed must include the rules passing was measured against.
